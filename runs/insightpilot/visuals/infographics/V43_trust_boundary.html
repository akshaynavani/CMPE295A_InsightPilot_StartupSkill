InsightPilot · Trust boundary

One arrow leaves, you choose what rides on it, and there is no write path to disable

The platform owner can end a purchase without attending a meeting, and he is convinced by artifacts rather than conversation. So the egress is written out field by field, the tradeoff is handed over rather than decided, and the things that are absent are distinguished from the things that are merely switched off.

The single egress, in two configurable modes
Mode one · minimum

Schema only

Column names
Column types
Column comments
The analyst's question text
No values of any kind
Cost of choosing this. Value-based schema linking gets weaker, so the resolver has less to disambiguate a term against and will ask the analyst more often.
Mode two · richer

Schema plus sampled values

Everything in mode one
Sampled distinct values per column
Columns flagged as personal data are excluded
Still no full result sets
Still no credentials
What it buys. Materially better term resolution, because the model can see that a region column holds four codes rather than six. The tradeoff is stated and handed to the customer, not decided for them.
Never crosses the boundary, under either mode
Database credentialsQuery result setsThe lineage record The binding storeThe audit logFile contents Columns flagged as personal dataAnything from another organisation

The model provider is reached on the customer's own API key, so whatever is sent sits under terms the customer already signed rather than a vendor's.

No write path exists Absent, not disabled. A disabled feature is one configuration away from enabled and a missing one is not. With a read-only role, the blast radius of a total compromise is what the analyst could already read.
No cross-organisation path exists Single tenant by construction rather than by policy. There is nothing to secure because there is no shared control plane. Add a managed offering later and this property is lost and has to be re-earned.
No authorisation is re-implemented The system connects under a role the customer provisions, and row and column permissions come from the source. Re-implementing authorisation inside an analytics tool is how one becomes a breach.
What a reviewer should notice
1
Count the arrowsOrchestration, all four agents, bindings, lineage, the audit log and every source connection run inside the customer environment. There is exactly one crossing.
2
The egress answers the second question, not the firstEveryone asks whether data leaves. The harder question is what exactly leaves, and the mode switch is the answer written as a configuration rather than a promise.
3
The audit log is a file, deliberatelyAppend-only on disk and readable without the application running. A quarterly access review took eight minutes against a day and a half for a comparable tool, and that gain depends entirely on being able to search a file.
4
A readable log is the cheapest governance enforcement availableHalf of projected agent-deployment failures by 2030 are attributed to insufficient runtime enforcement of governance. A greppable record is the least expensive form of it.
5
The veto is asymmetric, so the artifact has to arrive firstSaying no costs the platform owner nothing and ends the process. This page exists so the objection is answered before it is raised.
Why neutrality is a property here rather than a claim. Nothing in the boundary depends on trusting the vendor's intentions. It depends on where the code runs and which key it uses, both of which the customer controls and can verify.
What this does not claim, one

Not a compliance certification

No third-party attestations of any kind. The architecture is compatible with a customer's existing controls and carries none of its own, and any narrative artifact implying otherwise is wrong.

What this does not claim, two

It does not secure the model provider

Whatever the chosen mode sends is subject to that provider's terms. The contribution is making the egress minimal, explicit and configurable, not making it zero.

What this does not claim, three

It does not stop a malicious analyst

Someone with read access to the sources can already read them. The system records what they asked, which is more accountability than existed before and is not a control.
